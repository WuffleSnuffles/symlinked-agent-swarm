## 1. Executive Summary

Challenger 1 identified three critical defects that block passing the Milestone 4 Gate:
1. **Defect 1**: `courier submit` silently defaults to prompt `'Autonomous petition task'` and submits an unauthorized task when invoked without arguments, returning exit code 0 instead of returning error message and exit code 1.
2. **Defect 2**: `status` and `grid status` only check `.swarm/status/cubicles.json`, an obsolete/synthetic file path never generated by `CubicleManager` (which outputs `.swarm/roster.json` and `.swarm/status/cubicle-*.json`). Furthermore, the output is rendered as a 1D linear list instead of a 4x4 spatial matrix grid.
3. **Defect 3**: `/api/health` filters active cubicles using `c.assigned && c.state !== 'Error'`. On `CubicleLiveState`, `assigned` is undefined (it is `c.config.enabled`) and `state` is undefined (it is `c.status`). Consequently, `/api/health` always reports `cubicles_active: 0` in production.

This report documents the root-cause mechanisms, full evidence chain, exact remediation implementations, and comprehensive test suite design.

## 2. Evidence & Root-Cause Trace

### 2.1 Defect 1: `courier submit` Prompt Omission Rejection
- **Location**: `src/server/cli-dispatcher.ts:277-280`
- **Current Code**:
  ```typescript
  case 'courier_submit': {
    const agent = parsed.agent || 'openclaw';
    const prompt = parsed.prompt || 'Autonomous petition task';
    const requestedType = parsed.requestedType || 'BOTH';
  ```
- **Analysis**:
  When `SymlinkedAgentSwarm.exe courier submit` is run without arguments:
  - `parseCliArgs` parses no positional string, leaving `parsed.prompt === undefined`.
  - Line 279 uses `|| 'Autonomous petition task'`, silently fabricating a petition prompt.
  - The CLI proceeds to execute petition submission against the live swarm, creating unexpected tasks and returning `{ handled: true, exitCode: 0 }`.
  - Contrast with `courier status` (lines 343-348), which strictly verifies `if (!parsed.petitionId) { errLog(...); return { handled: true, exitCode: 1 }; }`.
- **Remediation**:
  1. In `parseCliArgs`: Support `--prompt` flag in addition to positional arguments, and parse `--workspace`.
  2. In `executeCliCommand`: Validate `if (!parsed.prompt || !parsed.prompt.trim())`. If invalid, output:
     `Error: task prompt is required. Usage: SymlinkedAgentSwarm.exe courier submit --agent <name> "<task>"`
     via `errLog` (which writes to stderr and logs buffer), trigger `if (exitOnComplete) process.exit(1);`, and return `{ handled: true, exitCode: 1, output: logs }`.

### 2.2 Defect 2: `status` Roster Deserialization & 4x4 Spatial Matrix Grid
- **Location**: `src/server/cli-dispatcher.ts:183-216`
- **Current Code**:
  ```typescript
  case 'status': {
    const cubiclesFile = path.join(swarmDir, 'status', 'cubicles.json');
    if (fs.existsSync(cubiclesFile)) {
      ...
    } else {
      log('[PANOPTICON] Swarm is offline or uninitialized (.swarm/status/cubicles.json not found).');
    }
  ```
- **Analysis**:
  - `CubicleManager.initialize()` (see `src/server/cubicle-manager.ts:58-60, 430-441`) persists cubicle configurations to `.swarm/roster.json` and per-cubicle telemetry to `.swarm/status/cubicle-01.json` through `cubicle-16.json`.
  - `.swarm/status/cubicles.json` is NEVER written by the live engine.
  - As a result, running `status` or `grid status` on any active swarm incorrectly logs `[PANOPTICON] Swarm is offline or uninitialized`.
  - Furthermore, when synthetic `cubicles.json` was provided, the output was a linear list rather than a 4x4 spatial matrix grid.
- **Remediation**:
  1. Check `.swarm/roster.json`. If present, read the 16 configs, enrich each config with status from `.swarm/status/${cfg.id}.json` (`status`, `fatigue_percentage`, `state`, `model`, `thinking_level`).
  2. Fallback to `.swarm/status/cubicles.json` if `.swarm/roster.json` is absent.
  3. Fallback to checking `.swarm/status/cubicle-*.json` via `CubicleManager` if needed.
  4. If cubicles exist, render:
     - Header: `PANOPTICON 4x4 CUBICLE SURVEILLANCE ROSTER MATRIX`
     - 4x4 Spatial Matrix Grid: 4 rows of 4 cubicle tags, e.g. `[cubicle-01: idle]   [cubicle-02: idle]   ...`
     - Divider line
     - Detailed Status Table with columns: `ID | ASSIGNED | MODEL | TIER | STATE | FATIGUE`
     - Footer and return `{ handled: true, exitCode: 0, output: logs, data: list }`.
  5. If no cubicles found, log `[PANOPTICON] Swarm is offline or uninitialized (.swarm/roster.json not found).` and return `{ handled: true, exitCode: 0, output: logs }`.

### 2.3 Defect 3: `/api/health` Active Cubicles Contract
- **Location**: `src/server/index.ts:171-189`
- **Current Code**:
  ```typescript
  app.get('/api/health', (_req: Request, res: Response) => {
    const allCubicles = cubicleManager.getAllCubicles();
    const activeCubicles = allCubicles.filter((c) => c.assigned && c.state !== 'Error').length;
  ```
- **Analysis**:
  - `CubicleManager.getAllCubicles()` returns `CubicleLiveState[]`.
  - `CubicleLiveState` interface (`src/server/types/cubicle.ts:97-113`):
    - `config.enabled: boolean` (indicates whether cubicle is enabled / assigned)
    - `status: CubicleStatus` (`'vacant' | 'idle' | 'working' | 'under_inspection' | 'error' | 'exhausted'`)
  - `c.assigned` and `c.state` do not exist on `CubicleLiveState` (evaluating to `undefined`).
  - Thus `c.assigned && c.state !== 'Error'` is always `undefined` (falsy).
  - `/api/health` always reported `cubicles_active: 0`.
- **Remediation**:
  Compute `activeCubicles` using:
  ```typescript
  const activeCubicles = allCubicles.filter(
    (c: any) =>
      (c.config?.enabled ?? c.assigned ?? false) &&
      c.status !== 'error' &&
      c.status !== 'vacant' &&
      c.state !== 'Error'
  ).length;
  ```
  On a default pre-populated swarm (`DEFAULT_CUBICLE_ROSTER`), cubicles 1, 2, and 3 have `config.enabled === true` and `status === 'idle'`. Cubicles 4-16 have `config.enabled === false` and `status === 'vacant'`.
  Therefore, `/api/health` evaluates to `cubicles_active: 3` and `active_cubicles: 3` deterministically.
